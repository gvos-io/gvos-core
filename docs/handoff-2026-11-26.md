## B 线现状（接手重点）

**根因已定位并修复（代码层面）**：`GVOS_MEDIA_OFF` 空字符串被 `#!trydefenv` 当"已定义"→ `#!ifndef` 跳过 → **媒体路径自 bench10（2026-11-22）起静默关闭**。证据：rtpengine 全历史日志 offer/answer 命令数 = 0（仅 52k query + 10k start-recording，全 Unknown call-id）。修复在 `deploy/kamailio-entrypoint.sh`：空值即 `unset GVOS_MEDIA_OFF`。

**接手会话（宿主机重启后）已完成**：Docker 恢复 → 重建 kamailio → SRTP e2e **PASS** → 转码 G722↔PCMU **PASS** → 录音 spool **PASS**。

**B 线额外根因（本会话钉死）**：
1. mr26 不认 `generate SDES` / `replace-session-connection` → offer=`replace-origin RTP/AVP DTLS=off codec-mask-all codec-transcode-PCMU`，answer=`replace-origin DTLS=off`
2. `t_continue()` 后 resume 是 FAILURE_ROUTE → `rtpengine_manage` 等价 delete；offer 必须走 `t_on_branch("RTP_OFFER")` + `branch_route[RTP_OFFER]`；answer 挂 `onreply_route`
3. 脚本踩坑：先注册再拨；`--srtp-secure=0`；`1000/demo1000`；非 DID 号 `8613800130000`；端口 env `25060/28081`
4. 录音：userspace 只能用 `--recording-method pcap`（`proc` → "kernel table not open"）；metadata 经 `--timeout` 从 `tmp/` 迁到 `metadata/`；`rtpengine-recording` 读 `/proc/rtpengine/...`，**无 xt_RTPENGINE 不出 MP3**。entrypoint 续行中勿夹 `#` 注释。
5. 录音 BYE：仅当 `meta=>rec:$ci==1` 时 `rtpengine_delete`（全量 BYE delete 曾在 100CPS 打出 BYE→408）。本 demo 拓扑下 pjsua↔SIPp 的 BYE 常不经 kamailio RR，依赖 timeout 收尾。
