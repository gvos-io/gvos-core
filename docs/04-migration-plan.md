# VOS 迁移方案：工具与切换流程

**版本**：v0.1（草案）
**日期**：2026-10-06
**上游依据**：`01-prd.md` §5 迁移日旅程；`research/research-international-competitors.md` VOS 生态栈

---

## 1. 为什么迁移工具是整个 GTM 的核心武器

VOS 客户 15 年不换系统的最大原因不是功能差距，是**数据搬不动**（几千个账户+余额、数万条费率、几十条网关/路由配置、历史话单）和**不敢停机**（话务是 7×24 生意）。谁把迁移成本打到接近零，谁就拿到替换市场。副武器：并行双跑消除"换系统账算错"的恐惧。

目标：**VOS 迁移全程 ≤ 2 人日客户侧投入 + 7 天并行期 + 30 分钟 cutover 窗口。**

## 2. 迁移对象清单

| 数据域 | VOS 侧来源 | 目标模型 | 难点 |
|---|---|---|---|
| 账户/多级代理结构 | VOS 客户端导出（账户列表含费率组、代理层级、信用额度） | 租户/代理/账户三级模型 | 代理层级语义映射（VOS 任意多级→我们支持 ≥5 级，超深层级打平提示） |
| 余额与预存款 | 账户余额导出 | 余额+冻结流水 | 迁移时刻的余额快照+在途通话对账 |
| 费率表 | 费率导出（前缀、费率、计费步长 60+6/6+6、生效时段） | 费率引擎（前缀最长匹配+时段+套餐） | 计费精度对齐（VOS 7 位小数进一制）；时长步长语义差异表 |
| 网关配置 | 网关导出（IP/端口/认证/并发限制/编码偏好） | 网关管理 | 大部分 1:1；编码偏好需人工确认 |
| 路由策略 | 路由组导出（优先级/比例/时段/失败重试） | 路由引擎 | VOS 的"落地路由/落地网关"两级概念映射 |
| 历史话单 | VOS CDR 数据库/导出文件 | 对象存储 Parquet（只读导入） | 不参与计费，仅供查询与对账 |
| IVR/回拨业务 | 业务包配置 | v1.0 不迁（记录 TODO，v2.0 IVR 编排承接） | 明确告知边界，防止预期错位 |

**注意**：破解版 VOS（客户实际跑的 2.1.x）与正版导出格式可能有差异——迁移工具按"实际数据库结构"读取（社区流传的数据库 schema 与导出样例已可获取），不依赖官方导出功能。这是隐性优势：**破解版用户的迁移路径比正版用户还顺**（转正话术闭环）。

## 3. 工具设计：`gvos-migrate`

一个 CLI/容器镜像（迁移本身免费，见 pricing §4）：

```
gvos-migrate extract    --source vos://(db-dsn|export-dir) --out snapshot/
gvos-migrate validate   --snapshot snapshot/ --rules rules.yaml   # 干跑校验
gvos-migrate plan       --snapshot snapshot/ --out migration-plan.md  # 差异报告
gvos-migrate load       --target https://g-vos-api --snapshot snapshot/ --dry-run
gvos-migrate compare    --vos-cdr ... --gvos-cdr ... --window 2026-XX  # 双跑对账
gvos-migrate cutover    --checklist  # 切换向导（DNS/网关指向/旧系统冻结只读）
```

**四步法流程**（销售/实施标准动作）：

1. **Extract + Validate（0.5 天）**：客户侧跑 extract（数据库只读账号即可），工具输出：
   - 数据体检报告：账户数/费率条数/网关数/层级深度/异常字段（空费率组、负余额、孤儿账户）
   - **语义差异清单**：VOS 与 G-VOS 计费语义不同之处逐条列出（例：VOS 某版本"首 6 秒不计费"的实现 vs 我们的计费起点规则），每条给"保持 VOS 行为"或"采用新行为"二选一（默认保持，保客户账务连续性）。
2. **Plan + Load dry-run（0.5 天）**：生成迁移计划给人审；dry-run 导入影子租户。
3. **并行双跑（7 天，可选 3 天加急）**：
   - 话务镜像：客户把一份拷贝话务（镜像 INVITE，经测试网关/回环落地）同时送 VOS 与 G-VOS——或者用**话单回放模式**（把 VOS 实时 CDR 喂给 G-VOS 计费引擎重算）。
   - `compare` 每日输出对账：逐账户话费差、逐费率条命中差、差异原因分类（计费语义差异/时间窗/网关路由差）。
   - **出口标准：差异话费 < 0.1% 且全部可解释。**
4. **Cutover（30 分钟窗口）**：网关侧指向切换（分批：先 10% 网关灰度 1 天，再全量）→ VOS 转只读 → 观察 24h → 完成。回滚方案：网关指回 VOS（VOS 侧数据冻结在 cutover 前，新话务不丢）。

## 4. 对账（compare）技术细节

- 输入：两边同时间窗 CDR（按 call-id/时间+主被叫模糊对齐，VOS CDR 无全局唯一 call-id 时用时间+号码+网关三元组）。
- 输出三层：①总账对齐（日收入差异 ppm）；②账户级（差异>阈值标红）；③话单级 diff 样本（前 100 条逐字段）。
- 已知不可消除差异（写进报告模板，销售提前管理预期）：媒体直通 vs B2BUA 的接续计时差、秒尾进位边界、VOS 盗版版行为异常话单。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| VOS 导出能力缺失/损坏（老系统） | 直连其数据库只读抽取；抽取前全量冷备份（工具内建 backup 步骤） |
| 并行期双跑成本客户不愿承担 | 话单回放模式（无需双份话务）；7 天并行含在首次实施服务价里 |
| 语义差异清单遗漏导致客户账务投诉 | 差异默认"保持 VOS 行为"；`compare` 出口标准卡 0.1%；每单留差异确认签字 |
| 中途回滚丢话务 | cutover 前 VOS 冻结快照；灰度分批切换；回滚演练是 cutover checklist 第一步 |
| 工具被白嫖（导完跑去别家） | 迁移免费但绑定 G-VOS 目标（load 需要 G-Vos License）；extract/plan 两步公开无妨——体检报告本身是获客钩子 |
