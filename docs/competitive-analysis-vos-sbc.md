## 0. 对标结论（一页版）

昆石产品线是**VOS（账房：计费/路由/账户经营）+ SBC（门房：边界安全/互通/媒体处理）互补两层**。G-VOS 以单系统同时覆盖两层职能，业务面已对齐或反超，管道面（容量标称）差一个数量级的验证。

四项核心差距（详见 §3）：

| # | 缺口 | 竞品参照 | G-VOS 现状 | 差距性质 |
|---|---|---|---|---|
| 1 | LCR 成本路由 | VOS「智能路由」核心卖点 | 仅优先级 + 故障冷却 | 功能缺失，工作量可控 |
| 2 | 容量标称 | 单机 2 万线并发 / 20 万在线注册 | 实测 1,000 并发 / 1,245 CPS burst | 验证缺口，路线图已有 |
| 3 | 媒体面生产化 | SBC 级媒体处理（转码/加密吞吐） | RTPengine spike 级 | 调优与验证，非架构 |
| 4 | （无差距项）实时对账/CDR 推送 | 2026-10 才加「实时智能对账 + UDP 推 CDR」 | 事件驱动原生形态 | **反超项**，非差距 |

排期原则：#1 是唯一的功能开发缺口，优先排期；#2/#3 是验证与调优工作，走 PRD 已有里程碑；反超项不排期，转化为营销叙事。

## 1. 昆石产品线全景（一手数据）

公司：南京昆石网络技术有限公司（Linknat），2005 年成立，软交换与计费系统厂商。

### 1.1 VOS 系（话务运营/软交换）

| 产品 | 定位 | 关键标称 |
|---|---|---|
| VOS5000 / VosPower | 超大运营商级 | 高性能协议栈 + 异步消息总线；核心数据 1:1 热备、信令/媒体 N:N-1 热备；单机 2 万并发线、20 万在线用户、单机语音转发 1 万线+ |
| VOS3800 | 中档 | 未细列 |
| VOS3000 | 经典款（20 年迭代） | 官方标称 5,000 带媒体并发、2 万在线话机；2026-10 V2.1.7.0 新增：实时智能对账、UDP 实时推 CDR、OTP |
| CKPBX | 云总机（PBX 段） | 企业办公通信，回电直通/一号多机/IVR 等 |
| 模块 | AXB 隐私号、动态黑名单增强、录音、IMS Edge、Web 接口、编码转换、IVR、智检云（质检 SaaS）、多数据源智能黑名单 | 按需选配 |

VOS 核心能力域（官网归纳）：电信级计费、智能路由、多级代理/账户、费率/套餐、CDR/报表、强制拆线、余额实时锁定、双机热备。

### 1.2 SBC 系（会话边界控制）

四个型号按容量/客群分档：SBC-S9800（运营商和大型行业用户）→ SBC-P9800 Pro（中大型企业）→ SBC-P9800（中大型企业）→ SBC-B500（中小企业）。功能向下包含。

关键能力域：拓扑隐藏、专有 SIP 防火墙、信令深度解码/编辑隔离、可视化信令跟踪、媒体 IP 独立映射、媒体多路径自定义、转码、DTLS 加密。S9800 标称：媒体转发 10 万线（20 万呼叫方）、双端独立加密 4 万并发呼叫 / 400 万 PPS。

定位关系：SBC 在网络边缘接 IMS/运营商/呼叫中心，VOS 在核心做计费路由。客户可单买其一或两套都部署——**昆石需要两套 SKU 凑齐「边界 + 经营」，G-VOS 单系统覆盖两层**。

### 1.3 客群对照

| | VOS 系 | SBC 系 |

## 2. VOS 功能逐项核对（代码为证）

核对基线：commit `aad932f` 工作树。✅ = 有且经测试；⚠️ = 有但受限；❌ = 无。

### 2.1 计费/账户域（昆石标称 7 子项）

| 昆石子项 | G-VOS | 代码证据 |
|---|---|---|
| 电信级计费 | ✅ | `internal/billing/charger.go`（步长计费）；`rate.roundUp7` 7 位小数第 8 位进一；容量报告 6,714 行 CDR vs 账本逐分零漂移 |

### 2.2 媒体旁路

✅ 架构同构：控制面（Go）与媒体面（RTPengine ×M）解耦，Kamailio `rtpengine_manage` 按需锚定媒体。
⚠️ 媒体面为 spike 级，生产级调优与大规模验证进行中（README 已声明，M0-M8 之后的路线图项）。

### 2.3 容量标称

| 指标 | 昆石 VOS5000 标称 | G-VOS 实测（capacity-report-2026-11-19） |
|---|---|---|
| 并发通话 | 2 万线 | 1,000 并发 × 30s 零失败、内存线性（+9MB） |
| 在线注册 | 20 万用户 | regtable 具备（`internal/regtable` 注册事件流 + Online 计数），20 万量级未验证 |
| 冲击 | — | 1,245 CPS burst 零失败；呼叫建立 p50 0.8ms / p99 2.9ms @ 100 CPS |
| CDR 落库 | — | burst 300 events/s，2.4s 追平积压 |
| 计费精度 | 电信级 | 逐分零漂移（369.78 = 369.78） |

差距为验证缺口而非架构缺口：应答延迟与对账质量反超（事件驱动 vs 事务路径）。

### 2.4 实时对账 + 实时 CDR 推送

✅ **反超项**。对账是架构不变量（CDR 流与账本两条独立持久化路径，持续可核对），非事后任务。CDR 外推走 NATS JetStream durable 队列（NAK 重投 + MaxDeliver 防毒丸 + 幂等落库），可靠性语义优于昆石 UDP 推送（无连接尽力而为）。昆石 2026-10 才补「实时智能对账」——竞品补课方向 = 本产品出生形态。

## 3. 差距与排期输入

### 3.1 P0 — LCR 成本路由（唯一功能开发缺口）

- **竞品参照**：VOS「智能路由」核心卖点；话批客户按分钟差价选路的日常操作。
- **现状**：`gw:prio` 纯优先级，无成本感知。
- **方案要点**：费率表已在内存（133ns/次 lookup）——把费率接入网关选择即可。落地为：网关选路时按「费率最低 → 优先级 → 故障冷却」排序；LCR 决策由控制面计算后随 cfg 广播下发 Kamailio（复用 `gvos.cfg.reload` 通道与 htable 机制），边缘不做费率查询。
- **验证**：新增单测覆盖「多网关多费率下选路正确性 + 费率变更即时生效」；容量报告补 LCR 开销项。
- **规模预估**：中（涉及 `internal/gateway`、Kamailio cfg、cfg 广播 payload，计费核心不动）。

### 3.2 P1 — 容量验证（已列 PRD 路线图，非新开发）

20 万注册 / 2 万并发线是话批客户问的第一个数字。按既有路线图执行公开压测（架构文档 §8），容量报告滚动更新。前置依赖：Redis 收口（`docs/redis-adoption-plan.md`）以支撑多副本容量与余额权威。

### 3.3 P1 — 媒体面生产化（已列 PRD 路线图，非新开发）

RTPengine spike → 生产级调优（转码策略、媒体锚定策略、资源隔离）。与容量验证同批推进。

### 3.4 反超项（不排期，转营销叙事）

- 单系统覆盖「VOS + SBC 职能」：IP 准入（CIDR/htable）+ Digest 认证 + 拓扑边界即 SBC 核心能力域。
- 事件驱动实时性：CDR 永不等库、逐分对账不变量。
- 这些进入 README/产品文案叙事，不进入开发排期。

### 3.5 排期总表

| 优先级 | 事项 | 性质 | 预估规模 | 前置 |
|---|---|---|---|---|
| P0 | LCR 成本路由 | 新功能 | 中 | 无（费率表已就位） |
| P1 | 容量验证 20 万注册 / 2 万并发 | 验证 | 大 | Redis 收口方案 |
| P1 | 媒体面生产化 | 调优 | 中-大 | 无 |
| — | 反超项叙事 | 文案 | 小 | 无 |

## 4. 市场空间（方向参考，数字未核实）

SBC 全球市场约 9–15 亿美元/年、低个位数 CAGR、Ribbon/Oracle/AudioCodes/Nokia 主导（训练知识，Dell'Oro 等机构口径，本次外网核实失败）。正面对标 SBC 红海性价比低；G-VOS 主战场在 VOS 段（话批/虚商/呼叫中心，分散无寡头、存量替换），SBC 职能作为内嵌能力输出，不单独立产品线。
