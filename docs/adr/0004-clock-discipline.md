# ADR-0004:多副本时钟纪律——单一事实时间源 + NTP 基线

**状态**:已接受(2026-11-19)

## 背景

多副本 + 月分区 CDR + 套餐 cycleKey 边界 + 风控日费用窗口(跨午夜)都依赖墙钟。各副本时钟漂移的后果:CDR 时间戳乱序(月分区错位)、套餐周期双计/漏计、日费用上限绕过(00:00 前后各算一天)。评审 F5 项(2026-11-19)。

## 决定

1. **单一事实时间源**:计费相关时间戳以 **gv-core 收到事件时刻的进程时钟为准**(呼叫开始/结束已在事件载荷带 Kamailio 侧时间,gv-core 落 CDR 时以自己时钟为权威、载荷时间为辅)——写入 02-architecture §4.2 的口径;
2. **NTP 纪律**:部署文档(operations-manual §5/§6)声明**所有 gv-core/Kamailio/PG 节点必须 NTP 同步,偏差预算 ±50ms**;compose-ha/K8s 形态节点默认 chrony/systemd-timesyncd,写进部署前置检查清单(baseline 脚本加一项);
3. PG 时钟不作为计费权威(now() 仅作审计行创建时间),避免"DB 时钟≠应用时钟"的经典分叉。

## 后果

- 成本:半天(ops 手册 + baseline 检查项 + CDR 落库路径的时间源注释);
- Redis Phase 2(多副本呼叫注册)实施前完成;cycleKey/日费用窗口的 key 由 gv-core 统一生成,Kamailio 不生成周期边界 key;
- 单机形态无感知;跨副本对账报告加"时钟偏差抽检"一节。
